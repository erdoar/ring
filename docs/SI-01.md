# SI-01 — Coding spec

**Causal residual subtraction for a console insert**

October 2026. This revision is the implementation contract. The survey that settled it is not repeated here. Code to this document. If a later change breaks an invariant in section 2, it is a design change and it gets written down before it is merged.

| | |
|---|---|
| Product | A macOS app. It opens the USB device. Not a VST3, not an AU, not an LV2. |
| Instance | One engine, one close voice. One to eight channels, not mixed. One mode for the device. |
| Operation | Subtract a capped residual from the microphone. Do not synthesize a new vocal. |
| Runtime files | None. Stored impulse responses are training data only. |
| Internal block | 128 samples at 48 kHz, fixed. The IO buffer is not. |
| Reported delay | 0 samples in ZERO. 127 samples in LOW. One number for every live channel. |
| First machine | M1, 8 GB unified memory. The app's own 32-sample IO buffer. |

## 1. What the code does

The microphone already contains the voice. The app recognizes voice only so it knows what it must not remove. The sample that leaves is still that microphone, minus a residual the process is willing to bet is not the voice.

```
out[n] = y[n] − cap( (g_tail ∗ y)[n] + howl[n] + bleed[n] )
```

`g_tail` is a short filter fit on audio older than the protected horizon. `howl` is a handful of biquad gains. `bleed` is one gain per band. ZERO uses the previous partition. LOW may use the 127-sample look. `cap` limits the broadband subtraction. If the voice gate is high, the step that would have moved `g_tail` is frozen, and `howl` and `bleed` stand down in the bands the gate has claimed.

A stem splitter does the other thing: it builds a new waveform and the singer you hear is the model's copy. Do not write that. A stored impulse response of the venue does the other thing again: it imposes an old room on a new one. Do not load one at runtime.

## 2. Invariants

These are tests, not advice. A build that breaks one is wrong even if it sounds better on a single file.

1. The audio callback does not allocate, lock, read a file, wait on another thread, or call the GPU or the Neural Engine.
2. The callback applies only a kernel published before this block. The fit never sees the samples it is about to play.
3. Reported device delay is exactly the mode: 0 or 127, the same on every live channel. The IO buffer is not added again, and it is not grown to buy CPU. Mode and buffer size change only while the stream is stopped.
4. The protected horizon is 128 samples, or the whole IO block if that block is larger. It is not "one callback" when the callback is smaller.
5. A voiced frame does not move the tail kernel, and a howl parked on a sung note is kept.
6. Broadband subtraction cannot exceed the cap. Default cap is 12 dB. A confirmed resonator may go deeper. Strength scales the caps. It is not a gate threshold.
7. Bypass matches the dry signal after the device delay, with a one-block ramp. A dead-room vocal with the process engaged matches bypass. LOW does not drop its 127 samples when bypassed.
8. One engine, one voice. At most eight engines in the process. They do not share a kernel and the voices are not summed.
9. On overrun, publish nothing. Keep the last kernel. Do not increase the buffer.
10. No weights, impulse responses, or code from a commercial plugin. Teachers used offline must be MIT or equivalent, and they never run during the show.
11. The quit list is a normal Quit of apps the user named. It does not run on the audio thread, does not force-quit, and does not touch WindowServer, coreaudiod, loginwindow, or Finder.

## 3. Settled choices

Do not re-open these in the first implementation.

- Notches are a safety net on the console, not this plugin.
- A loudspeaker-reference feedback canceller needs a tap this insert does not have. Steal only the freeze-on-voice rule.
- A true inverse, and a time-reversed impulse response, are out. Both are the wrong equation at this latency.
- The tail is weighted prediction error, or a partitioned frequency-domain adaptive step of the same shape: predict the present from audio older than the horizon.
- Howl is a resonator bank, not a bin in the tail FFT. A short transform cannot separate a howl from a harmonic a few hertz away.
- Bleed, if it is learned at all, is a causal student of an offline vocal mask. The student outputs band gains. The residue loss wins when the two disagree on a harmonic.
- Place the insert after the channel EQ that feeds the PA, and before the compressor. Compression in front lifts residue into the voice.
- Honest gain, if phase 1 works, is 6–12 dB more usable level on a difficult lav or headset, as a range across rooms. Not 40 dB. Not one demo.

## 4. Objects

Plain data. No plugin-framework types in this layer, so a test can run the block without a host.

```
struct Kernel {
  float tail[TAIL_TAPS];     // 512 taps, 48 kHz, about 10.7 ms
  float howlGain[HOWLS];     // 8 resonators, linear gain, 1 = pass
  float howlHz[HOWLS];
  float bleed[BANDS];        // 16 bands, 1 = pass
  uint32_t seq;              // odd while being written, even when published
};

struct VoiceGate {
  float likelihood;          // 0..1, from the previous partition
  float band[BANDS];         // per-band claim, 1 = this band is voice
};

struct Fifo {
  float samples[PART * 2];   // PART = 128
  int fill;
};
```

`TAIL_TAPS` is 512. `HOWLS` is 8. `BANDS` is 16. `PART` is 128. These are constants, not parameters.

Two `Kernel` slots. The audio thread reads `published`. The worker writes `staging` and then publishes by swapping an index. The sequence counter is the only synchronization: the reader retries if it observes an odd value. No mutex in the callback.

The FIFO absorbs host blocks until 128 samples are present. A 32-sample callback fills it four times and runs the tail fit once. A 128-sample callback fills it once. A host block larger than 128 is processed in 128-sample slices, and the horizon protects the entire host block.

## 5. The callback

```
process(y, n, mode):
  if bypass: copy y to out, ramp, return
  g = read_published()                 // retry on odd seq
  for i in 0..n-1:
    tail = fir(g.tail, y[i])           // history already excludes the horizon
    h    = resonators(g, y[i])         // howl gains from last publish
    b    = bands(g.bleed, y[i])
    sub  = cap(tail + h + b, strength, g)
    out[i] = y[i] - sub
  fifo.push(y)
  update_resonators(y, n)              // howl tracking is every host block
  if fifo has PART new samples and mode allows a publish:
    hand the worker a copy of history older than HORIZON
    // do not wait
```

`HORIZON` is 128 samples in ZERO. In LOW it is still 128 of protected voice, and the plugin additionally delays the output by 127 samples so the bleed gains may look inside that declared window. Report `setLatencySamples(0)` or `setLatencySamples(127)`. Do not report the partition.

The FIR reads a delay line that has already dropped the newest horizon. Implementing "do not let the fit see the future" by accidentally letting the FIR see it is the bug this line exists to prevent.

## 6. Rebuilding the kernel

The worker runs on a performance core. It never runs on the audio thread.

Input: microphone samples older than the horizon, a few hundred milliseconds, and the voice gate from the partition before this one.

Tail:

```
g_tail = argmin || y[n] − (g ∗ y_old)[n] ||
```

`y_old` is delayed by at least `HORIZON`. Minimize with a few iterations of a partitioned frequency-domain step, or one weighted-prediction-error update at partition rate. Same shape either way: drive down what the present still shares with the older audio.

If `likelihood` is above the freeze line, take a zero step on the tail. A vowel is predictable for a few periods. An open step will decide the vowel is the residue.

Howl, on the audio thread, every host block: track up to 8 partials. A partial may lower `howlGain` only when it is narrow, persistent across partitions, and `band[k]` at that frequency is low. Vibrato, a moving formant, or a syllabic envelope sets the band high and the gain stays at 1. When the cues disagree, keep the note.

Bleed: multiply by `bleed[k]` from the last publish. Phase 1 hard-codes `bleed[k] = 1`. Phase 3 replaces that with the student. The slot exists now so phase 3 is not a rewrite.

Publish at the next partition boundary. If the worker has not finished, do not publish. Stale by one partition is about 2.7 ms. That is the designed miss. A missed howl update is not acceptable, which is why the resonators do not live on the worker.

## 7. Block size

Accept any IO block from 16 to 2048 samples. Preallocate for 2048 when the device opens. The app sets the size at the start. On the M1 that size is 32. If it has to change, stop the stream, drop the FIFO, keep the last kernel, and do not fit until a full partition has arrived after the restart. A half-filled partition looks like a transient and the resonator bank will grow a false partial.

Do not expose a control that changes the IO buffer. ZERO and LOW are the only latency controls, and they apply only while the stream is stopped. An automatic mode that hunts for a larger buffer is forbidden.

## 8. Machine

Code the first version for an M1 with 8 GB, at 48 kHz, with the app's own 32-sample IO buffer.

The live state is about 100 KB per voice. Eight engines in this process must finish inside the block, each in ZERO, the device reporting 0. The Apple vDSP FFT is the one to call. A portable FFT library is allowed in tests and is not the optimized path.

The 8 GB budget is the rest of the machine, not the kernel. Do not map a stem model into the same process. Loading one will page, and a page fault in the callback is a dropout. The offline teacher is another program. Asking other apps to quit, if the user has named them, happens before the stream starts and never from the callback.

Pin the audio thread and the worker to performance cores. Leave the efficiency cores alone. Do not enqueue Metal or the Neural Engine while the insert is open: a large GPU footprint evicts the cache the kernel is supposed to live in.

## 9. Parameters

| Id | Range | Default | Meaning |
|---|---|---|---|
| `channels` | 1..8 | 1 | Set while the stream is stopped. One engine each |
| `bypass` | bool | false | Dry, delayed by the device report |
| `mode` | zero, low | zero | Device delay 0 or 127. One mode for every channel |
| `strength` | 0..1 | 0.5 | Scale on the caps, not a threshold |
| `dereverb` | 0..1 | 0.35 | Scale on the tail only. Lower it on in-ears |
| `freeze` | bool | false | Hold the kernel where it is. For a known-good moment, not a normal state |

No input gain, no output gate, no frequency display that invites notch-drawing. A meter may show voice likelihood, tail subtraction in dB, and whether the last publish was missed. That is the debugging UI.

## 10. What is not in the show

Training is a separate program. It does not ship inside the audio callback.

1. Record dry sung and spoken voices that you have the right to use.
2. Record your own room responses, plus any impulse-response pack whose license allows commercial use. Convolve. Null the dry voice. The leftover is the tail target.
3. Add synthetic poles that grow, including poles that sit on a sung note. Those files are the howl teacher and the adversarial test.
4. Optional, and only after phase 1 has a measured gain: run an MIT vocal mask offline. HTDemucs is MIT. A Mel-Band RoFormer checkpoint is allowed only when its own card says MIT. Unlicensed community checkpoints are listening references, not teachers. Distill band gains, past frames only. If the mask and the residue loss disagree on a harmonic, the residue loss wins.

Stored responses are practice. They are not loaded when the app opens.

The quit list is not a process scanner. The user writes the names. Opening at login is a system login item and does not itself quit anything.

## 11. Tests that gate a merge

Run these without a DAW, on the plain objects in section 4.

| Test | Pass |
|---|---|
| Dead room | Engaged output equals bypass, within a null deeper than −60 dB, on a dry vocal |
| Identity of the horizon | The fit's input buffer does not contain the newest 128 samples |
| Voiced freeze | A steady vowel does not move `g_tail` after the gate opens |
| Note on a howl | A partial with vibrato keeps `howlGain` at 1 |
| Growing tone | A stationary partial that rises, with likelihood low, is reduced |
| Cap | Broadband subtraction never exceeds the strength-scaled cap |
| Block change | 32 to 128 to 32 produces one crossfade and no residual partial |
| Overrun | A worker that never finishes leaves the previous kernel in place and still returns audio |
| Delay report | ZERO reports 0, LOW reports 127, at 44.1, 48, and 96 kHz. Every channel in one opening reports that same number |
| Bypass ramp | Engaging or leaving bypass does not click, and does not change the device delay |
| Engine count | Eight engines, 32-sample blocks, 48 kHz, complete inside the block on the target machine |

The listening set, not automated, ships beside them: two voices on one instance, breath and plosives, a tambourine meant to stay, compression before the insert. Those are allowed to sound wrong. They are not allowed to howl, click, or replace the voice with a resynthesis.

Gain-before-feedback is a range on a repeatable loop: speaker, microphone, raise level until the open loop howls, then again with the process on. Report the distribution. A single afternoon on one lav is a data point, not the spec.

## 12. Suggested layout

```

src/dsp/tail.cpp        the fit and the FIR
src/dsp/howl.cpp        resonators, audio-thread update

```

The app's job is the device, the buffer, the one device delay, the parameters, the quit list, and the snapshot. If the DSP needs an AppKit type, the boundary has already been crossed. The package is `SI01/`.

## 13. Order of work

Each phase ends when its tests are green. Do not start the next phase to rescue a red one.

**Phase 1. Kernel.** Tail, resonators, bleed, and LOW are in the note. Exit remains the tests in section 11. If a dry vowel cannot hold, do not open a device.

**Phase 2. The app.** The Swift package. One to eight engines. One mode. IO buffer fixed at 32 samples on the M1. Device delay equals the mode. No window while the stream is up. The quit list stays off the audio thread, and it is not part of the login item.

**Phase 3. The snapshot, then the desk meter.** Twice a second to an iPad, on the console Wi-Fi or a network the Mac broadcasts. No samples. Then time this insert on the desk. Refuse to call a path legal for ears when the number says it is not.

**Not scheduled.** A VST3 or AU wrapper, a hardware bypass relay, a GPU model, a stored venue IR, a control for the IO buffer, a force quit, a dummy display, Sidecar as the meter.

## 14. Latency numbers the meter is checked against

The app's processing delay is not included. The IO buffer is included. Do not add it twice. The interactive bench in the note uses the same rows.

| Path | Figure | Use |
|---|---|---|
| MADI, SQ-6 bench | 1.9 / 2.6 / 3.9 ms at 16 / 32 / 64 | The number to beat. Measured. |
| Hardware Dante, same bench | 2.5 / 3.2 / 4.5 ms | A real insert. Measured. |
| Wing USB | about 7.3 ms at 32 samples | Edge of in-ears. Reported. |
| Scarlett-class analog | about 5 ms | The escape hatch when console USB is a recording port. Reported. |
| SQ-6 USB | about 18–20 ms | Speech only, or change the transport. Measured. |

Ears are inside at ≤ 5 ms and marginal until 8. Wedges inside at ≤ 8 ms. Front of house, the vocal group delayed as one piece, inside at ≤ 12 ms. The meter prints the class. It does not print "USB zero latency."

## 15. Session

The process is a login agent. Setup may open a window. Starting the stream closes it. The display may sleep. The system may not. A dummy display keeps the GPU compositing, so do not add one.

The login item starts the app and nothing else. Asking other apps to quit happens only after the process is up, and only if that option is on. The audio thread does not ask.

These names are never asked, even if typed: WindowServer, coreaudiod, loginwindow, Finder. The ask is a normal Quit. There is no force.

## 16. Snapshot

Twice a second. One WebSocket text frame. The console's own Wi-Fi, or a network the Mac itself broadcasts. Not guest Wi-Fi, where clients often cannot see each other. Bind the listener to that interface.

The callback writes a fixed block and a counter. It does not allocate, lock, or send. The other thread sends only when the counter is even. `missed` and `overrun` stay latched until that send succeeds. A torn or failed send leaves them in place. The frame contains no samples. If the iPad stops drawing, the insert is unchanged.

```
{"seq":1,"channels":1,"delay":0,"mode":"zero","likelihood":[0],"cutDb":[0],"missed":0,"overrun":0,"pressure":"normal","thermal":"nominal"}
```
